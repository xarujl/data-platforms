# Автоматизация YARN поверх HDFS

Ansible-деплой добавляет YARN и MapReduce к уже работающему HDFS из `hw1`. Он не устанавливает Hadoop или Java, не меняет `core-site.xml` и `hdfs-site.xml`, не форматирует NameNode и не перезапускает HDFS.

## Состав кластера

| Группа inventory | Узлы | Добавляемые демоны |
| --- | --- | --- |
| `namenode` | `nn` (`10.35.0.11`) | ResourceManager, NodeManager, JobHistoryServer |
| `workers` | `nn`, `dn0` (`10.35.0.12`), `dn1` (`10.35.0.13`) | NodeManager на каждом узле |

Узлы доступны с edge под пользователем `team` через `~/.ssh/team_internal`, как и в автоматизации hw1.

## Предварительные условия

- HDFS из `hw1` запущен; NameNode видит три живых DataNode.
- На всех трёх узлах установлены Hadoop 3.4.0 в `/opt/hadoop-3.4.0`, Java 11 и настроенный `hadoop-env.sh`.
- На узлах есть системный пользователь `hdfs`, группа `hadoop`; `team` может выполнять команды через `sudo` без интерактивного пароля.
- На машине запуска установлен `ansible-core`.

Playbook проверяет эти условия и останавливается с ошибкой, если исходный HDFS не готов.

## Запуск с edge

Скопируйте репозиторий на edge, затем:

```bash
cd data-platforms/hw2/infra
cp inventory.ini.example inventory.ini
```

Проверьте приватные адреса в `inventory.ini`, пользователя `team` и путь к SSH-ключу. Затем выполните:

```bash
./deploy.sh
```

Для дополнительной диагностики можно передать стандартные аргументы Ansible, например:

```bash
./deploy.sh --check --diff
```

`--check` полезен для предварительной оценки конфигурации, но не может подтвердить создание HDFS-путей или регистрацию демонов.

## Что выполняется

`site.yml` последовательно запускает:

1. `preflight.yml` — проверка Hadoop/Java, пользователя `hdfs`, группы `hadoop` и трёх живых DataNode.
2. `configure.yml` — создание локальных каталогов NodeManager, установка `mapred-site.xml` и `yarn-site.xml` на все узлы, создание HDFS-каталогов истории JobHistoryServer.
3. `start.yml` — запуск демонов по ролям, проверка веб/RPC-портов и ожидание трёх зарегистрированных NodeManager.

Повторный запуск безопасен: конфигурация и каталоги приводятся к заданному состоянию, уже работающие демоны не запускаются повторно. Если XML-конфигурация изменилась, соответствующие YARN-службы перезапускаются; HDFS-службы не затрагиваются.

## Ручная проверка задания MapReduce

После успешного деплоя на NameNode можно выполнить WordCount из инструкции `../manual-installation.md`, шаг 9. Также проверьте веб-интерфейсы через SSH-туннель, описанный в шаге 10 той же инструкции.

Остановка и повторный запуск демонов выполняются адресно командами из шага 11 `../manual-installation.md`.
